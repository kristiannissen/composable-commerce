# Composable Commerce

An experiment in building a headless B2B commerce platform as standalone
services, driven by AI agents under strict human oversight. One engineer,
small budget, sandbox only. Design phase, nothing final.

## Architecture

Stateless, standalone services. A service knows another only through its
published event and `schema.json` contract; no shared code, no shared
module. Communication is asynchronous events; drift is caught by generated
contracts and tests, not by review.

Data lives in one database instance with one schema and one DB role per
service, granted only its own schema. No cross-service tables, FKs or
queries, ever.

| Service | Responsibility | Publishes | Consumes |
|---|---|---|---|
| Catalog | Products/variants, search docs, signed prices | `ProductUpdated` | — |
| Merchant | B2B accounts, CVR + VIES validation, discounts | `MerchantApproved` | — |
| Checkout | Cart validation (MOQ, pack sizes), VAT, order creation | `SalesOrderPlaced` | — |
| SalesOrder | Order ledger, state machine | `SalesOrderInvoiced`, `SalesOrderRequiresManualAction` | `SalesOrderPlaced` |
| Accounting | Invoice sync, idempotency, manual-action handling | — | `SalesOrderPlaced` |
| Notification | Alerts for manual-action orders | — | `SalesOrderRequiresManualAction` |

The storefront is headless: static-first, selective server rendering,
HMAC-signed requests through a single gateway. Net prices never render for
anonymous visitors. Frontend types are generated from service contracts in
CI, so contract drift is a failed build.

## Agentic pipeline

Spec before code, verified twice: Gate A approves intent, Gate B accepts
behavior. Agents are stateless LLM calls in narrow roles, driven through
chats and sessions first, scripted into Artisan commands only once a
step repeats:

```text
INSTRUCTIONS.md            human notes, business and technical, per module
  -> requirements chat     Vibe Work + .ai/prompts/requirements.md
  -> Gate A                human approval of requirements.md
  -> gherkin chat          derived .feature; steps only from .ai/steps.md
  -> build session         coder agent (Vibe Code / Pi) to green:
                           lint, Pint, PHPStan, Pest, arch, Behat
  -> Gate B                human acceptance slice; push only on ok
                           (diagnosis-based attempts, max 3 runs + 1
                           escalation when stuck)

Periodic:
  -> manual audit          whole diff + .ai/hardening/CHECKLIST.md
```

Spec agents never see code; the coder sees one module folder and contracts
only; step definitions are hand-written and protected, no LLM writes test
code; every LLM output is verified by a script or by a human. The same
failure twice earns a check: conventions grow only from repeated real
failures. Scripts earn their place the same way: an ai:* command exists
only after the manual step it wraps has repeated.

## Folder structure

```text
composable-commerce/
├── AGENTS.md                        # house rules, agents read this first
├── docs/
│   ├── Architecture.md              # services, events, data, testing
│   └── Pipeline.md                  # agentic pipeline and rationale
├── .ai/
│   ├── conventions.md              # hard rules for all agents
│   ├── steps.md                    # step vocabulary
│   ├── prompts/                     # one prompt per agent role
│   ├── vendors/                     # external API facts, the only API source
│   └── hardening/
│       ├── CHECKLIST.md             # manual audit + escalation reference
│       └── OPEN.md                  # unresolved advisory findings
├── tests/
│   └── Behat/
│       ├── LaravelContext.php       # base context
│       └── Steps/                   # hand-written step library (protected)
├── .github/
│   └── PULL_REQUEST_TEMPLATE.md     # proof form
├── apps/
│   ├── api/                         # Laravel application
│   │   ├── app/Console/Commands/    # make:module; ai:* when earned
│   │   ├── config/ai.php            # roles, models, budgets
│   │   ├── routes/api.php           # /api/health only
│   │   └── modules/
│   │       └── <Module>/
│   │           ├── INSTRUCTIONS.md  # business + technical notes (human)
│   │           ├── MODULE.md        # card, facts generated by ai:deliver
│   │           ├── schema.json      # published event/query contracts
│   │           ├── <Module>ServiceProvider.php
│   │           ├── requirements.md  # approved by Gate A
│   │           ├── <module>.feature # approved Behat spec
│   │           ├── Actions/ Events/ Listeners/ Models/ Migrations/
│   │           ├── routes.php
│   │           └── Tests/{Unit,Behat}/
│   └── web/                         # headless storefront
│       └── src/types/              # generated from schema.json in CI
└── .githooks/
```
